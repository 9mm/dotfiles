# Rules

- Think axiomatically from first principles.
- Always build the simplest, most direct implementation first. No abstractions, wrappers, helpers, or layers until there's a concrete need for them. Less code and less indirection is better.
- Always use domain-driven design.
- Never run `rm` or `rmdir` with variables or interpolation that could wipe the root drive if mistyped.
- Never commit for me.
- Don't use jargon or overloaded words whose meaning depends heavily on context.
